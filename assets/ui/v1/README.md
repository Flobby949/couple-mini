## 如何叠加

### 双人签到

1. `checkin-fabric-panel.png` 作为背景装饰，保持 2:1 原比例。图片内部不含头像、数字、连接线、文字或按钮。
2. 头像为单独圆形容器；可以使用示例头像，也可换成真实用户上传的图片。
3. `avatar-stitch-frame.png` 放在头像上层；中间和外侧都透明。参考预览：头像直径约为绣边画布的 72%，居中对齐，使头像边缘被绣边稍微覆盖。
4. 昵称、签到状态勾、连接线、积分、按钮由真实前端元素叠加。不可用更换整张底图的方式实现签到状态。
5. 底板按自然比例放在签到账面的插画区域，按钮和额外说明可排列在该区域下方。内容变高时不要纵向拉伸绣边或压扁人物。

预览页的组合仅演示图层关系。生产布局仍以页面说明为准，不将预览页作为业务实现。

### 头像与装饰

- `avatar-woman.png` 与 `avatar-man.png` 是可替换的示例人物，**不代表角色与性别绑定**。不要按这两个文件创建用户记录。
- 头像建议圆形裁切；绣边仅在签到/关系区域使用，普通列表头像可以只用圆形裁切。
- 植物猫咪装饰仅在有空间的标题角落使用，保持比例且不遮挡通知铃或文字。
- 积分罐用于“共同积分池”，不用于个人余额、支付或店铺收入。
- 完成徽章带有固定勾形图案，仅用于已完成/达成结果的装饰；页面仍需真实文字表达状态，徽章不能当作可勾选控件。
- 空店与空任务图下方由前端显示当前角色对应的说明和操作。不把“新建商品”画入插画。

### 商品封面

四张照片可放入用户手动选择的封面素材列表；不自动创建“抱抱”等商品，不写入默认价格或库存。可复用为开发视觉示例，但必须与真实业务数据分开。

封面原图为正方形。商品卡优先方形裁切；详情可按容器比例裁切，并检查拥抱双方、按摩双手、游戏手柄或餐桌主体仍在画面内。使用居中裁切作为起点，需要时按真实容器微调焦点。

## 尺寸与导出

本包保留生成原图，约 **19.75 MiB**。这是素材源文件体积，不是建议整包进入客户端的资源预算。开发时按实际使用尺寸导出并按需引用。

| 用途 | 推荐导出起点 |
| --- | --- |
| 最大显示 112px 的头像 | 336 × 336，保留透明与圆形容器裁切 |
| 最大显示 128px 的绣边/徽章 | 384 × 384，保留 Alpha |
| 最大显示 72px 的积分罐 | 216 × 216，先确认细节在小尺寸下可读 |
| 200–240px 空态插画 | 按比例导出，宽 600–720px |
| 398px 宽签到底板 | 1194 × 597，保持比例 |
| 200px 宽角落装饰 | 600 × 300，保持比例 |
| 商品封面 | 列表与详情按各自容器导出；原图支持常见手机展示尺寸 |

这些是按约 3 倍显示尺寸给出的导出建议，不是文件名中的固定倍率。实际导出格式、压缩质量、加载方式和缓存策略在目标前端接入时确定。本轮没有修改图片内容的脚本处理，也没有声称已完成小程序包体优化。

## 清单约定

`manifest.json` 每条记录包含：

- `id`、`file`：稳定标识与相对此目录的文件路径。
- `width`、`height`、`mime`、`bytes`、`sha256`：实际文件元数据。
- `hasTransparency`、`alphaRange`：读取 PNG 后得到的透明通道结果，不是根据扩展名推断。
- `usage`、`display`、`fit`：使用位置、建议显示尺寸与缩放方式。
- `reference`、`sourceFile`：参考页面与生成来源，供追溯，不作为运行路径。

装饰图语义为空，由页面文字提供信息；头像的可读名称来自当前用户，商品封面的可读名称来自商品名称。状态不能只靠图片或颜色表达。
