# 实施记录

2026-10-21，分支 `codex/initial-implementation`。按前端架构的阶段顺序，从工程及契约推进到绑定、规则与签到闭环，尚未完成全部 MVP。

## 已落地

- Go + Gin 模块化后端、MySQL 版本迁移、Redis 七天会话、健康检查、受控本地开发登录与微信 code 登录适配。
- 一次性邀请码绑定，两个人账户、100 分共享池、两家空店在同一事务建立。无解绑换绑、无预置商品。
- 固定规则提议、另一方确认、其他待确认提议作废；上限 0 有效；修改不重置当日数据。
- 签到、双人奖励、累计里程碑、池子与流水原子写入；统一北京时间。
- 原请求指纹、成功/拒绝回执、查询与关闭仲裁；前端未知结果持久恢复，关闭与迟到请求并发验证。
- Taro 4.3 + React 18 + TypeScript、TanStack Query、原生四 Tab、登录/绑定/规则/首页/积分池明细，按当前页面显示状态刷新。
- 外观设置：跟随系统/浅色/深色；鸢尾紫/青绿/杏橙；本地保存，页面、状态提示及原生导航/TabBar 同步适配。
- 业务事件同事务保存到 Outbox；当前待办从规则、订单和任务状态聚合。

## 第二轮：小店到订单

第一轮已提交为 `7fcd242`。本轮继续在同一开发分支实现：

- 私有图片上传、解码限制、持久文件标识与带会话读取；换图不覆盖历史文件。
- 本人商品创建/编辑、伴侣小店、库存与积分价校验；服务端持久购物车，每次只选一个商品一份，下单后移除当前候选。
- 下单改价校验、原价快照、库存与积分原子扣减；接单、拒单、兑现、驳回、收货及三天自动确认。
- 下单方接单前直接取消、接单后申请取消；店主审批或主动取消，原额退款、返库存及适用的半额罚分全额入池。
- 取消申请与自动确认计时的互斥；驳回和重提废弃旧计时，拒绝取消重新给三天；历史回执和当前状态分别读取。
- 订单历史、个人积分流水、首页订单待办与双方视角的列表；所有页面沿用明暗和三种主题色。
- 后台调度按启动注入的回调扫描自动确认，接口读写前也先独立补齐到期订单，不让后续业务失败撤销到期转换。

## 第三轮：任务与赠送

第二轮已提交为 `58d0c5f`。本轮继续在同一开发分支实现：

- 共同任务按双方奖励合计预留，伴侣任务按执行方奖励预留；接受前由发布方编辑，按差额调整预算，无实质变化不写业务历史；接受后锁定约定。
- 接受/拒绝、提交/确认、驳回补正；共同任务不限时，伴侣任务严格早于未来绝对截止时刻提交，驳回需新的未来补正期限。
- 取消申请独立于主阶段，既不冻结操作也不暂停截止；审批绑定具体申请 ID，终态自动作废未处理申请。
- 未接受到期只释放，已接受超时释放全部预留并向执行方扣奖励半额向上取整（可为负），罚分全额入池；待确认阶段免超时。
- 实际奖励按确认当天各自剩余额度发放，未发放部分释放回可用；预留转移与真实池子收支分开展示，保留不可变实际结算回执。
- 伴侣赠送不扣本人或池子，每人每天三次（0 分/实际到账 0 也占次数）；单次按当前上限 20% 四舍五入，接收方与任务共享每日获得额度，超额丢弃。
- 任务列表/待办/历史、创建编辑与详情、个人中心伴侣设置和赠送、个人/共享流水关联跳转、操作未知结果恢复；沿用明暗与三种主题色，H5 日期弹层和说明输入继承主题。
- 订单与任务统一独立补结算；绑定后的关系操作先锁关系再锁操作人，避免双人交叉确认/赠送时外键检查形成锁环。绑定竞争仍先按固定顺序锁用户，并在绑定刚提交时重新按关系顺序进入。

## 第四轮：消息中心与提醒偏好

第三轮已提交为 `db21c9d`。本轮实现：

- 业务事务注入只读快照捕获器，冻结有效渠道默认值、昵称、接收人和业务结果；中立事件值包不依赖业务服务。提交后事件总线独立事务生成通知/渠道记录及消费收据，单订阅者退避、故障留存；旧版事件缺失快照明确跳过。
- 消息列表/未读/全文、按发生时间分页、打开后标读、快照集合全部已读；首次R02仅开放对应提议标读，其他业务仍遵守首次规则门禁，直达目标在门禁后恢复。
- 30个独立模板的四渠道偏好、逐模板详情、微信映射能力、用户点击单模板订阅、授权结果本机待同步与稳定报告去重、最近微信投递状态。所有新页面沿用明暗及三种主题色。
