# 实施记录

2026-10-21，分支 `codex/initial-implementation`。按前端架构的阶段顺序，从工程及契约推进到绑定、规则与签到闭环，尚未完成全部 MVP。

## 已落地

- Go + Gin 模块化后端、MySQL 版本迁移、Redis 七天会话、健康检查、受控本地开发登录与微信 code 登录适配。
- 一次性邀请码绑定，两个人账户、100 分共享池、两家空店在同一事务建立。无解绑换绑、无预置商品。
- 固定规则提议、另一方确认、其他待确认提议作废；上限 0 有效；修改不重置当日数据。
- 签到、双人奖励、累计里程碑、池子与流水原子写入；统一北京时间。
- 原请求指纹、成功/拒绝回执、查询与关闭仲裁；前端未知结果持久恢复，关闭与迟到请求并发验证。
- Taro 4.3 + React 18 + TypeScript、TanStack Query、原生四 Tab、登录/绑定/规则/首页/积分池明细，按当前页面显示状态刷新。
- 外观设置：跟随系统/浅色/深色；鸢尾紫/青绿/杏橙；本地保存，页面、状态提示及原生导航/TabBar 同步适配。
- 业务事件同事务保存到 Outbox；当前待办从规则状态聚合。

## 本轮验收边界

自动化覆盖见 README。小程序和 H5 构建通过不等于开发者工具或真机通过。微信账号凭据、体验成员、HTTPS 合法域名、真实登录和订阅模板仍需接入；上传与受控媒体访问属于后续小店阶段。

本轮已运行真实 MySQL/Redis 集成与 Go race/vet，前端 35 项单测与 TypeScript 检查，以及双端生产构建。检查了小程序 `theme.json` 引用和两端各 48 个主题图标完整打包。浏览器实际走通开发登录、绑定、零上限规则生效与双人签到；已检查 390px 深色青绿、320px 浅色杏橙和刷新后外观持久保留。尚未做系统主题事件的真机验证、大字体/键盘全场景或微信开发者工具验收。

绑定、规则、签到 API 与自动化事务用例已经具备；任务和购物 Tab 当前是明确的建设中页面。通知消费者、消费收据、30 模板偏好、微信投递及后台调度尚未实现，事件暂不发送通知。

## 下一阶段

1. 小店与订单：图片上传/受控读取、商品与库存、服务端购物车、单件下单与价格核对、订单快照、取消退款与半额罚分、三天自动确认。
2. 任务与赠送：预留预算、两类任务、接受/提交/确认/补正、独立取消申请、即时到期补结算、每日额度及赠送次数。
3. 消息：冻结接收人/偏好与模板上下文、提交后独立消费事务和消费收据、消息中心、30 模板偏好、微信授权与投递状态。
4. 真机与发布：验证小程序生命周期、分包直达、窄屏/大字/键盘、安全区、登录、图片与订阅；备份恢复和服务器部署。

后续涉及超时罚分的用例，必须先在独立事务补齐到期结算，再执行原业务请求，不能仅依赖定时扫描，也不能让原业务失败回滚已生效的到期结算。
