# 实施记录

2026-10-21，分支 `codex/initial-implementation`。按前端架构的阶段顺序，从工程及契约推进到绑定、规则与签到闭环，尚未完成全部 MVP。

## 已落地

- Go + Gin 模块化后端、MySQL 版本迁移、Redis 七天会话、健康检查、受控本地开发登录与微信 code 登录适配。
- 一次性邀请码绑定，两个人账户、100 分共享池、两家空店在同一事务建立。无解绑换绑、无预置商品。
- 固定规则提议、另一方确认、其他待确认提议作废；上限 0 有效；修改不重置当日数据。
- 签到、双人奖励、累计里程碑、池子与流水原子写入；统一北京时间。
- 原请求指纹、成功/拒绝回执、查询与关闭仲裁；前端未知结果持久恢复，关闭与迟到请求并发验证。
- Taro 4.3 + React 18 + TypeScript、TanStack Query、原生四 Tab、登录/绑定/规则/首页/积分池明细，按当前页面显示状态刷新。
- 外观设置：跟随系统/浅色/深色；鸢尾紫/青绿/杏橙；本地保存，页面、状态提示及原生导航/TabBar 同步适配。
- 业务事件同事务保存到 Outbox；当前待办从规则状态聚合。

## 第二轮：小店到订单

第一轮已提交为 `7fcd242`。本轮继续在同一开发分支实现：

- 私有图片上传、解码限制、持久文件标识与带会话读取；换图不覆盖历史文件。
- 本人商品创建/编辑、伴侣小店、库存与积分价校验；服务端持久购物车，每次只选一个商品一份，下单后移除当前候选。
- 下单改价校验、原价快照、库存与积分原子扣减；接单、拒单、兑现、驳回、收货及三天自动确认。
- 下单方接单前直接取消、接单后申请取消；店主审批或主动取消，原额退款、返库存及适用的半额罚分全额入池。
- 取消申请与自动确认计时的互斥；驳回和重提废弃旧计时，拒绝取消重新给三天；历史回执和当前状态分别读取。
- 订单历史、个人积分流水、首页订单待办与双方视角的列表；所有页面沿用明暗和三种主题色。
- 后台调度按启动注入的回调扫描自动确认，接口读写前也先独立补齐到期订单，不让后续业务失败撤销到期转换。

## 本轮验收边界

自动化覆盖见 README。小程序和 H5 构建通过不等于开发者工具或真机通过。微信账号凭据、体验成员、HTTPS 合法域名、真实登录和订阅模板仍需接入；上传与受控媒体访问属于后续小店阶段。

首轮已运行真实 MySQL/Redis 集成与 Go race/vet，前端 35 项单测与 TypeScript 检查，以及双端生产构建。检查了小程序 `theme.json` 引用和两端各 48 个主题图标完整打包。浏览器实际走通开发登录、绑定、零上限规则生效与双人签到；已检查 390px 深色青绿、320px 浅色杏橙和刷新后外观持久保留。尚未做系统主题事件的真机验证、大字体/键盘全场景或微信开发者工具验收。

本轮新增真实 MySQL/Redis 订单事务用例与媒体边界测试，前端累计 42 项单测。独立 Chrome 窗口已走通商品编辑、受控封面显示、加入购物车、单选 0 分下单、申请取消、拒绝后重新确认及收货完成，并检查深色购物与订单页。已复现并验证来源价格 0 → 1 的跨页面改价提示；商品表单临时隐藏保留组件和草稿，仅暂停提交，微信生命周期仍待真机验证。浏览器扩展缺少“Allow access to file URLs”权限，自动文件选择未完成；上传通过真实 API 和集成测试验证，未改动浏览器权限。微信真机的选择/上传/下载仍待接入验证。
