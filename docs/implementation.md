## 第三轮：任务与赠送

第二轮已提交为 `58d0c5f`。本轮继续在同一开发分支实现：

- 共同任务按双方奖励合计预留，伴侣任务按执行方奖励预留；接受前由发布方编辑，按差额调整预算，无实质变化不写业务历史；接受后锁定约定。
- 接受/拒绝、提交/确认、驳回补正；共同任务不限时，伴侣任务严格早于未来绝对截止时刻提交，驳回需新的未来补正期限。
- 取消申请独立于主阶段，既不冻结操作也不暂停截止；审批绑定具体申请 ID，终态自动作废未处理申请。
- 未接受到期只释放，已接受超时释放全部预留并向执行方扣奖励半额向上取整（可为负），罚分全额入池；待确认阶段免超时。
- 实际奖励按确认当天各自剩余额度发放，未发放部分释放回可用；预留转移与真实池子收支分开展示，保留不可变实际结算回执。
- 伴侣赠送不扣本人或池子，每人每天三次（0 分/实际到账 0 也占次数）；单次按当前上限 20% 四舍五入，接收方与任务共享每日获得额度，超额丢弃。
- 任务列表/待办/历史、创建编辑与详情、个人中心伴侣设置和赠送、个人/共享流水关联跳转、操作未知结果恢复；沿用明暗与三种主题色，H5 日期弹层和说明输入继承主题。
- 订单与任务统一独立补结算；绑定后的关系操作先锁关系再锁操作人，避免双人交叉确认/赠送时外键检查形成锁环。绑定竞争仍先按固定顺序锁用户，并在绑定刚提交时重新按关系顺序进入。

- 微信逻辑层缺少 `AbortController`，React Query 在发请求前中断，查询保持 pending/idle，首页只有加载提示。新增仅小程序启用的标准兼容层，并直接引用实现入口，避开包的浏览器入口对原生 DOM 全局对象的假设。独立测试在删除内置构造器后复现相同故障，再验证请求结果发布、取消信号和保留已有原生实现。
- 原生 WXSS 中依赖 `> *` 的分段按钮和订单快捷项未应用样式，出现深色白底和文字换行。改为明确的子元素样式类，同时修正任务筛选、操作区和日期选择器；产物检查禁止再引入通配选择器。
- 页面隐藏后仍因主题变化改写当前页原生标题。原生导航及主题更新限定在可见页，回到 Tab 页恢复底栏；购物页隐藏时关闭抽屉，导航后清理抽屉时处理原生底栏 API 已不可用的情况。
- 插画被打包为长 Base64 并通过渲染数据传输，模拟器产生大属性警告。改为包内文件路径，集中声明并显式复制 8 张实际使用的插画；动态头像和图标尺寸统一经过 Taro 的响应式换算。

- 微信选图失败返回普通对象而非 Error，导致权限错误被静默忽略。平台层现在区分取消与权限失败，并保留大小限制和本地路径验证。
