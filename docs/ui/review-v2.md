## 业务含义核对

| 核对项 | 结果 |
| --- | --- |
| 池子与预留 | 260 = 200 可用 + 60 预留；不将预留释放重复计算为新增预算 |
| 共同任务 | 40 约定 = 10 + 20 实际到账 + 10 释放，按各人额度分别处理 |
| 个人流水 | 33 + 20 + 15 + 21 - 21 = 68；当天获得 20 + 15 = 35，不把退款算入额度 |
| 商品改价 | 21 → 30 需再次确认；68 - 30 = 38 |
| 店主主动取消 | 21 × 50% 四舍五入为 11；5 - 11 = -6；同意下单方取消不按此罚分 |
| 任务取消 | 申请不覆盖主阶段、不暂停截止，可继续依法处理；拒绝取消不回滚最新状态 |
| 订单取消 | 待处理时不提交兑现、不自动完成；原待确认被拒绝取消后重算 3 天 |
| 零值边界 | 上限、奖励、赠送和价格允许 0；负余额不能下 0 分商品；库存必须足够 |
| 赠送上限 | 103 / 5 取整为 21；上限 0、1、2 时单次最多 0；0 分赠送计次 |
| 通知设置 | 12 订单 + 12 任务 + 3 赠送签到 + 3 绑定规则 = 30 个独立模板 |
| 累计签到 | 7/30/100/365 天分别额外入池 30/100/300/1000；漏签不清零 |

上述示例计算和模板数量已用脚本校验。另经独立设计复核，修正二级页面返回入口及完整通知列表入口，并对校正版重新目视检查。角色和状态转换按 PRD 对照，不能用这些数值检查代替业务测试。
