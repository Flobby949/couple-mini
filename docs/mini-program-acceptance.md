2026-10-21，在微信开发者工具 Stable 2.02.2608080、基础库3.17.5、iPhone 12/13模拟器中执行。使用新的本地开发身份和正常业务API准备数据；没有直接修改开发库余额、库存或订单时间。隔离工程沿用已授权的本地域名校验设置，仓库配置保持校验开启。

## 消费分支

| 场景 | 原生交互与核对结果 |
| --- | --- |
| 店主拒单 | 确认弹层说明原额退款、不罚分；拒单后退1积分、返1份库存，拒绝终态与历史正确 |
| 店主接单、兑现及买方收货 | 店主原生接单、提交兑现，买方原生确认非零积分收货；已完成且库存不回补 |
| 买方接单前取消 | 原生确认取消后退1积分、返库存，不罚分 |
| 店主接单后主动取消 | 5积分订单原额退买方，店主罚3积分；余额0→-3，共同池80→83，个人及共同流水一致 |
| 待兑现同意取消 | 店主原生同意后原额退款、返库存，无罚分 |
| 待收货同意取消 | 店主原生同意后原额退款、返库存，撤销自动确认计时 |
| 待兑现拒绝取消 | 店主原生拒绝后恢复待兑现，无收货计时；随后原生提交兑现正常 |
| 待收货拒绝取消 | 店主原生拒绝后恢复待收货，从拒绝时重新给予72小时；原生页显示的新期限与服务端一致 |
| 买方接单后申请取消 | 待兑现及待收货均在原生页面提交，提交时不退款；申请中不再显示买方收货/重复申请操作 |
| 驳回兑现与重提 | 买方原生驳回后回到待兑现、旧计时撤销；店主通过API重提，买方原生页看到新三天期限并确认完成 |
| 改价 | 原生结算页原价2，店主API改为3；页面刷新后明确显示2→3和“确认以新价3积分下单”；实际扣3，取消原额退3、返库存 |
| 积分不足 | 余额15选择999积分商品，购物车明确说明不足，确认按钮禁用 |
| 负余额与免费商品 | 余额-3选择0积分商品，提示需先恢复到非负，禁止结算 |
| 零库存 | 原生商品详情提示暂无库存、禁用立即下单 |

三天自动确认、取消期间不自动确认、到期补结算与失败回滚由真实MySQL/Redis集成测试的可控服务端时钟验证，未宣称在模拟器中真实等待三天。其他列明的手工分支均通过原生界面执行关键操作，准备状态及未列为原生操作的对方步骤由业务API完成。

## 修复与回归

- 绑定输入步骤补充页内“返回邀请页”，解决原生首次页面没有返回栈时无法切回生成邀请码。
- 订单取消及兑现说明区分店主与下单方，店主不再看到等待自己处理申请或请自己确认收货的文案。
- 商品名称改为保持原有排版的原生按钮，详情具备独立可访问入口；加入购物车仍独立处理，不重复触发详情导航。
- 商品保存后返回调用页，并为直接进入编辑页保留小店回退地址。原先保存会重复压入小店路由，原生页持续加载且返回会再次落到已保存编辑页；复现不依赖选图，已以导航回归测试约束。

- 赠送仅在金额与次数均有效时显示预计到账，避免超过单次上限或当天次数耗尽时仍显示不可能的到账预览。
- 赠送结果返回记录列表时，回退到栈中已有页面；未在栈中的列表替换当前页。同样用于消息详情和模板详情的返回列表入口，避免重复页面导致后续按钮无响应。已验证返回后再次打开原详情；直接进入时的替换回退由自动测试覆盖。
