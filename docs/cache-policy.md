# 后端读取缓存

缓存使用现有 Redis，数据库仍是事实来源。缓存命中可跳过对应查询；接口仍会鉴权、获取关系锁、处理到期结算，并实时读取需要的积分数据。

| 数据 | 最长有效期 | 失效条件 |
| --- | --- | --- |
| 已绑定的伴侣关系 ID | 72 小时 | 当前绑定关系不可变；不缓存未绑定结果 |
| 双方资料 | 72 小时 | 修改资料；关系阶段、规则额度、累计双签天数从已锁定的关系行获取，服务器时间和北京时间业务日期每次重新计算 |
| 规则列表及指定提议 | 72 小时 | 新提议、确认规则 |
| 商店商品列表及商品详情 | 72 小时 | 新增/编辑商品、下单、取消/拒绝订单或同意取消导致退库存；列表与详情共同失效 |
| 图片访问元数据 | 72 小时 | 只缓存成功授权；图片元数据和已绑定关系不可变，文件仍检查实际存在性 |
| 单笔积分赠送详情 | 72 小时 | 记录不可变 |
| 用户通知渠道偏好 | 72 小时 | 修改对应用户的渠道设置；事件捕获仍使用数据库中的当前偏好 |
| 当日签到状态 | 2 小时 | 任一方签到；缓存字段包含北京时间业务日期和查看人 |
| 任务首屏列表、详情、时间线、首页任务待办 | 2 小时 | 新增/编辑任务、任务动作、到期结算 |
| 订单首屏列表、详情、时间线、首页订单待办 | 2 小时 | 下单、订单动作、自动收货结算 |
| 积分赠送列表 | 2 小时 | 新的赠送记录 |

余额、积分池、积分额度和奖励预览、交易写入校验、购物车、账单、通知与订阅剩余次数继续实时查库。任务和订单携带分页游标的请求直接查库，避免为任意游标积累缓存。

用户相关缓存包含用户 ID，关系内共享数据包含关系 ID；任务和订单列表字段还区分查看人、角色和筛选条件，不跨用户复用可执行动作。媒体授权按查看人和文件 ID 隔离。

可变数据在持有关系锁时读取、回填和失效。写入在释放锁之前清除同组缓存，防止并发读取在清除后又回填旧数据；事务回滚只会多一次缓存未命中。前台读取与后台定时结算共用失效逻辑，不等待缓存到期才更新任务或订单状态。

命中不续期；同一缓存组新增字段也不延长原有有效期。空列表可以缓存，查询错误和无权访问结果不缓存。Redis 读写失败时回源数据库并记录日志；失效失败时，旧展示数据最长保留至 TTL 到期，交易写入仍使用数据库校验。

商品详情在列表回源时预热：利用列表已查出的完整商品数据，批量写入同一关系缓存中的详情字段，不为预热增加商品查询。列表字段使用 `list:<ownerId>`，保证旧格式列表首次访问时也能建立详情缓存；命中列表后不重复预热或续期。直接打开详情时按需查库并缓存该商品，不加载整店数据。详情只缓存商品信息，余额按查看人实时读取；下单仍实时校验价格、库存和余额。预热只使用已提交数据，不在商品写事务提交前回填。
