# 后端读取缓存

缓存使用现有 Redis，数据库仍是事实来源。缓存命中可跳过对应查询；接口仍会鉴权、获取关系锁、处理到期结算，并实时读取需要的积分数据。

| 数据 | 最长有效期 | 失效条件 |
| --- | --- | --- |
| 已绑定的伴侣关系 ID | 72 小时 | 当前绑定关系不可变；不缓存未绑定结果 |
| 双方资料 | 72 小时 | 修改资料；关系阶段、规则额度、累计双签天数从已锁定的关系行获取，服务器时间和北京时间业务日期每次重新计算 |
| 规则列表及指定提议 | 72 小时 | 新提议、确认规则 |
| 商店商品列表及商品详情 | 72 小时 | 新增/编辑商品、下单、取消/拒绝订单或同意取消导致退库存；列表与详情共同失效 |
| 图片访问元数据 | 72 小时 | 只缓存成功授权；图片元数据和已绑定关系不可变，文件仍检查实际存在性 |
| 单笔积分赠送详情 | 72 小时 | 记录不可变 |
| 用户通知渠道偏好 | 72 小时 | 修改对应用户的渠道设置；事件捕获仍使用数据库中的当前偏好 |
| 当日签到、当前月双方记录 | 2 小时 | 关系键内的v2字段包含日期/月初与数据库checkin_revision；签到事务递增版本，旧版本不可再命中，DEL仅作清理 |
| 已结束月份的签到记录 | 72 小时 | 独立checkin-history关系键；首次封存读取重新查库，不直接提升未结束月份缓存；当前不允许补签或修改 |
| 任务首屏列表、详情、时间线、首页任务待办 | 2 小时 | 新增/编辑任务、任务动作、到期结算 |
| 订单首屏列表、详情、时间线、首页订单待办 | 2 小时 | 下单、订单动作、自动收货结算 |
| 积分赠送列表 | 2 小时 | 新的赠送记录 |

余额、积分池、积分额度和奖励预览、交易写入校验、购物车、账单、通知与订阅剩余次数继续实时查库。任务和订单携带分页游标的请求直接查库，避免为任意游标积累缓存。

用户相关缓存包含用户 ID，关系内共享数据包含关系 ID；任务和订单列表字段还区分查看人、角色和筛选条件，不跨用户复用可执行动作。媒体授权按查看人和文件 ID 隔离。签到缓存只存userId/date/mood/checkedAt原始行，每次在鉴权后按当前查看人映射me/partner；serverTime、businessDate、firstMonth及当前昵称都不从这份记录缓存读取。

可变数据在持有关系锁时读取、回填和失效。写入在释放锁之前清除同组缓存，防止并发读取在清除后又回填旧数据；事务回滚只会多一次缓存未命中。前台读取与后台定时结算共用失效逻辑，不等待缓存到期才更新任务或订单状态。

命中不续期；同一缓存组新增字段也不延长原有有效期。空列表可以缓存，查询错误和无权访问结果不缓存。Redis 读取缓存失败时回源数据库并记录日志；其他组失效失败时，旧展示数据最长保留至 TTL 到期，交易写入仍使用数据库校验。签到组每次从已锁定关系行读取revision，写入、版本与回执同事务提交；即使DEL失败，也不会再读到旧版本字段。登录会话仍依赖Redis，不把读取缓存回源能力解释为Redis完全不可用时仍能登录。

前端月历key为`['checkins','month',actorId,coupleId,month]`，当前月staleTime30秒、历史月Infinity，gcTime30分钟；现有应用级invalidate仍可使历史月失效。可见页面利用context每15秒的版本变化刷新当前月，隐藏时停止查询；签到确认、回前台和跨北京时间日界线刷新相关事实。历史数据只在QueryClient内存，不混进持久图片缓存。

公共心情图使用内容版本URL与ETag，H5复用HTTP缓存；微信端缓存已验证尺寸、格式与长度的PNG到用户文件目录。文件key包含origin/版本/亮暗/心情，同键请求去重、最多2个下载并发，最多保留2个版本、32个文件和4MiB，优先清理旧版；本地文件丢失/损坏可重取，写盘或索引失败降级临时文件。公共插画可跨账号复用，独立于受控头像/封面的按用户缓存；登出仍会清除私有查询与私有媒体缓存。

商品详情在列表回源时预热：利用列表已查出的完整商品数据，批量写入同一关系缓存中的详情字段，不为预热增加商品查询。列表字段使用 `list:<ownerId>`，保证旧格式列表首次访问时也能建立详情缓存；命中列表后不重复预热或续期。直接打开详情时按需查库并缓存该商品，不加载整店数据。详情只缓存商品信息，余额按查看人实时读取；下单仍实时校验价格、库存和余额。预热只使用已提交数据，不在商品写事务提交前回填。
